## 0. 一页纸总览

```
                        ┌─── 前置冻结模块（不参与梯度）────┐
  单目 RGB (多人同框) ──►│  人脸检测 + 跟踪 → K_t 条轨迹    │──► 每脸: 脸/嘴 crop + 头姿/注视 + valid 标志
                        └───────────────┬─────────────────┘
                                        ▼
                              ┌────────────────────┐
                              │ 视觉塔（共享权重）  │──► v_k[t] ∈ R^3072   每脸每 80ms 一个 token
                              └─────────┬──────────┘
                                        │
       ★ 常驻 others 流: v_others = 可学习嵌入（无脸、无注视）───┤ 零初始化门控 cross-attn
                                        │                      第 k 条流只看自己的 v
  多人混合音频 ──►[Whisper enc ×1]──►[adapter]──►┌──────────────────────────────┐
     16 kHz        （全部流共享，只跑一次） 12.5Hz │  Voxtral LLM 26 层 d=3072     │
                                       80ms/tok  │  ★ batch = K_t 张脸 + 1 others │
                                                 │    各自 KV cache               │
                                                 └───────────────┬────────────────┘
                                                                 ▼ H_k[t]  每流独立 hidden
                                        ┌───────────────────────────────────────┐
                                        │ forward 只吐 logits（每流 × 每帧）     │
                                        │  asr_logits   [B,K+1,T,131072]        │
                                        │  state_logits [B,K+1,T,3]             │
                                        │  addr_logits  [B,K+1,T,2]             │
                                        └───────────────────────────────────────┘
                                                     ← 模型到此为止；解码与仲裁属系统层（§3.5）
```

**一句话**：混合音频只编码一次，**每张脸各开一条被自己视觉条件化的 LLM 流，再加一条常驻的
`others` 流兜住画外声音**；每条流独立地回答"这段混音里属于我的是什么、我说完没、我在对谁说"。

**★ 为什么要 `others`**：没有它，"画面里三个人都沉默、画外有人在说话"这种情形**无处安放**——
K 条流全输出 PAD，那段音频凭空消失。`others` 把"音频的归属"从**部分覆盖**变成**完全覆盖**，
于是画外语音有了**正样本监督**（others 转写它），而不只是靠所有脸输出 PAD 的负样本监督。

## 1. 输入契约 ✅

### 1.1 音频

| 项 | 值 | 依据 |
|---|---|---|
| 形态 | **多人混合**单通道波形，16 kHz | cvpr-framing §1（不用麦阵 / DoA） |
| 前端 | Whisper-large-v3 编码器，`num_mel_bins=128`，`hidden=1280`，32 层 | `config.json: audio_config` |
| 降采样 | adapter `downsample_factor=4` → LLM token 流 | `config.json: downsample_factor` |
| **帧率** | **12.5 Hz = 80 ms / token** | `audio_length_per_tok=8 × hop_length=160 ÷ 16000`（`inference.py:118-119`） |
| LLM | `hidden_size=3072`，26 层，`vocab=131072` | `config.json: text_config` |
| **前瞻延迟** | `default_num_delay_tokens=6` → **480 ms** | `inference.py:122`；对齐规则见 §2.4 |

> **★ 音频编码器只跑一次。** K 条流吃的是同一份 `input_features`，
> Whisper 编码器（32 层 / 1280 维）与 adapter 属**共享前缀**，`1×`；
> 只有 LLM 解码器是 `K×`。这是 B 路线成本的真实构成（§7.4）。

### 1.2 视频

| 项 | 值 |
|---|---|
| 形态 | **单目 RGB**，多人同框 |
| 前置模块（冻结、不训） | 人脸检测 + 跟踪 → 第 t 帧给出 `K_t` 条稳定轨迹 |
| 每条轨迹产出 | ① 脸/嘴 ROI crop；② 头姿 + 注视向量；③ **`valid_k[t] ∈ {0,1}`**（是否拿到可信人脸） |
| 时间对齐 | 重采样到 **12.5 Hz**（25 fps → 每 80 ms 取末帧；50 fps → 池化） |
| `K_t` | **变长**，0 起步，允许人中途进出（流的生老病死见 §2.5） |
| **流的总数** | `K_t + 1`（K 张脸 ＋ 常驻 `others`），**恒 ≥ 1** |

**`valid_k[t]` 是契约的一部分，不是实现细节**：它驱动 §4 三种情形的分流，
也决定 addressee 输出是否可信（无脸 / 极侧脸 → 注视不可读 → addressee 必须弃权，见 §3.4）。

## 2. 中间流程

### 2.1 视觉塔 💡（选型待拍板，接口已定）

```
crop_k[t]  ─►[视觉编码器: 预训练唇动/脸动塔]─► e_k[t] ∈ R^d_v
pose_k[t]  ─►[小 MLP]───────────────────────► g_k[t] ∈ R^d_g
                  concat → Linear(d_v+d_g → 3072) → v_k[t]
valid_k[t] = 0  ⇒  v_k[t] := 0            # 硬置零，不是学出来的
```

- 编码器候选：💡 **AV-HuBERT 视觉前端**（唇动，96×96 ROI，自监督预训练，输出序列表征）
  vs Light-ASD / TalkNet（ASD 预训练，但输出偏二分类 logit，不适合当条件源）。
- **注视/头姿走独立支路**，不能被唇动塔吞掉 —— addressee 轴只靠它（cvpr-framing §3.2）。
- 每脸每帧 **1 个 token** 起步；不够再升到 n 个（超参，不改契约）。

### 2.2 per-face 条件化 —— ★ 核心机制 ✅

**面孔 k 的 visual token，通过零初始化门控 cross-attention 注入第 k 条流的 LLM 各层。**

```
第 k 条流、LLM 第 ℓ 层（每 N≈4 层插一个）:
    h ← h + tanh(α_ℓ) · CrossAttn(Q = h, K = V = v_k[≤t])      α_ℓ init 0
```

- **因果**：位置 t 只看 `v_k[≤t]`。
- **零初始化**：`α=0` 或 `v_k≡0` 时该流**逐比特等于纯 X2-Turn**。
  这一条同时是：恒等性单测（§6.1）、视觉失效的降级保证（§4.1）、以及 K=0 情形的定义。
- **`others` 流同构**：它走**完全相同**的注入路径，只是 `v_others` 来自一个**可学习嵌入**而非视觉塔（§2.6）。
- **流间不共享、不通信**：第 k 条流只看 `v_k`，**没有任何 cross-face 注意力**。
  这是与 MuVAP 的结构性差异（它把 N 人塌成 2 态；我们任意 K、置换等变、不塌）。
- **新增参数**只有：视觉塔 + 门控 cross-attn + 三个头；骨干走 LoRA。

> **⚠️ 新颖性口径（不可犯）**：该机制 = **AV-TSE 的表征空间版本**，机制**不新**
> （CueNet / Plug-and-Steer / USEF-TSE，cvpr-framing §7）。论文**绝不能**写
> "首个视觉引导 per-face 提取/路由"；卖点钉在**输出是 per-face 语义状态而非波形**。

### 2.3 为什么不加 cross-face 归一化 ✅

自然的诱惑是在 K 条流之间做 softmax（"这帧属于谁"）。**不做**，两条理由：

1. 真重叠时多人同时说，"归一化到 1"是错的前提 —— 这正是 VAP 家族塌成 floor-holder 的起点。
2. **不需要**：静默脸的 ASR 标签是**全 PAD**（§5.3），这个监督已经在惩罚"抢别人的话"，
   竞争信号从标签进来，不必从结构进来。

保持 forward 逐脸独立 = 保住"真 per-face、任意 K"这条卖点。

### 2.4 ⚠️ 时间对齐（最容易静默写错的地方）

**只用一条索引规则，不发明第二套**：X2-Turn 的读出偏移是

```
prediction_index = prefix_length + frame_index - 1        # inference.py:165，next-token 语义
```

→ **墙钟帧 `i` 的 visual token 注入到 LLM 位置 `prefix_length + i - 1`**，与音频帧 `i`、
状态读出位置**完全同一位置**。`num_delay_tokens=6`（480 ms）内生在音频特征的排布里，
意味着模型在该位置已看到 480 ms 的音频前瞻 —— 视觉按同一位置注入，就自动获得**同样的前瞻**，
视听前瞻一致。写错则视听错位 480 ms，且**不报错、只静默掉点** → 由 §6.2 脉冲响应单测兜住。

### 2.5 流的生老病死（变长 K 的流式处理）✅

| 事件 | 处理 |
|---|---|
| 新轨迹出生（有人进画面） | **新开一条流**，KV cache 从当前时刻冷启动（不回放历史）。前几百 ms 该流的语义上下文弱，`state` 置低置信 → 系统层按 uncertain 处理 |
| 轨迹存活 | 该流持续增量解码，维护自己的 KV cache |
| 轨迹丢失 / 人出画面 | 该流**销毁**，KV cache 释放 |
| 短暂遮挡（`valid=0` 但轨迹未死） | 流**保留**，`v_k[t]:=0` → 这几帧退化为纯音频行为，恢复后继续 |
| 人离开又回来 | **算新轨迹、新流**（v5 起就不做身份 enroll / re-ID，保持最简） |

⚠️ **冷启动是 B 路线的固有代价**：新出现的脸拿不到它出现之前的音频上下文。
⏳ 是否需要"有界回放"（新流补跑最近 N 秒音频）留作实现期实验，不进 v6 契约。

### 2.6 ★ 常驻 `others` 流（画外说话人）✅

**定义**：除画面内 K 张脸外，恒定再开一条流，代表"**声音属于某个我看不见的人**"。

```
v_others[t] = E_others ∈ R^3072        # 单个可学习嵌入，全时刻常数，随模型训练
```

它与人脸流**结构完全同构**（同一套门控 cross-attn、同一套三个头），差别只有三处：

| | 人脸流 k | `others` 流 |
|---|---|---|
| 条件来源 | 视觉塔吃 crop + 头姿 | **可学习嵌入**（无脸、无注视、无 crop） |
| `addressee` | 由注视/头姿决定 | **永久弃权** —— 看不见的人，注视无从判断 |
| 存在性 | 随轨迹生灭 | **常驻**，`K_t=0` 时它是唯一的流 |

**它买到了什么**（三条，按重要性排）：

1. **补上归属的完全覆盖**。原设计里 `K≥1` 张脸全沉默 + 画外有人说话（旧 §4.3d）**无流可去**，
   那段音频凭空消失。现在它落进 `others`。
2. **把负样本监督升级为正样本监督**。原来只能靠"所有脸输出全 PAD"这种负向信号来教模型
   "这不是你说的"；现在同时有"**这是 others 说的**"的正向目标，对 §7.2 的退化解是更强的约束。
3. **消掉 `K=0` 特例**。流的集合恒非空，`max(K_t,1)` 那个补丁没了，
   三种运行情形变成同一套机制的三个取值（§4）。

**诚实的限制**（必须写进论文，别被审稿人捅）：
- **多个画外说话人会被压成一条流** → 此时 `others` 拿到的又是混合表征，其 completeness 不可信。
  这是可接受的：setting 的前提就是"要交互的人在画面内"，画外是**残差桶**，不是一等公民。
  系统层应把 `others` 的 `complete/incomplete` 一律按低置信处理。
- **`others` 不承担非语音噪声**。定义严格限定为"**不能归到任何可见人脸的语音**"；
  环境噪声/电视/关门声 → 所有流（含 others）判静默。

**与"纯音频降级"的关系（两件事，别混）**：

| 触发 | 行为 |
|---|---|
| 视觉**可用**但画面无人（`K_t=0`） | `others` 流带**可学习嵌入**运行 —— 语义是"没人露面，但有人在说" |
| 视觉**整体失效**（相机故障/全黑/前置模块崩） | 全部 `v := 0`（含 `v_others`）→ 门控无贡献 → **逐比特退化为纯 X2-Turn** |

后者才是降级保证，也是 §6.1 恒等性单测测的东西。⚠️ 注意 `E_others` 非零，
所以"`K=0` 的 others 流"**不等于**"纯 X2-Turn"——这是 v6.1 相对 v6 改掉的一处语义。

⏳ **留作升级项**：让 `E_others` 额外看到"当前可见人脸集合"的池化表征（置换不变，
不破坏 §2.3 的无归一化原则），使它能更明确地做"排除这些人之后的残差"。先不做，保持最简。

## 3. 输出契约 ✅（forward 只吐 logits）

对每条流 `k ∈ {face_1..face_{K_t}} ∪ {others}`、每个 80 ms 帧 `t`：

| 输出 | 形状 | 实现 | 热启动 |
|---|---|---|---|
| `asr_logits` | `[B,K+1,T,131072]` | 复用 `base_model.lm_head` | ✅ 继承 X2-Turn |
| `state_logits` | `[B,K+1,T,3]` | **新** `Linear(3072,3,bias=False)` | ✅ 拷 `vad_lm_head` 第 35/37/38 行 |
| `addr_logits` | `[B,K+1,T,2]` | **新** `Linear(3072,2,bias=False)` | ❌ 随机；`others` 行永久弃权 |

三个头在人脸流与 `others` 流之间**共享权重** —— `others` 的差异全部由 `E_others` 承载。

### 3.1 状态三态 ✅
`{0 静默 · 1 说话-incomplete · 2 说话-complete}` —— active 与 completeness 天然耦合，单头即可。

**热启动**：`vad_lm_head` 是 `lm_head` 的整词表拷贝，只有 id 35–40 有意义
（`modeling.py:15-23`：`idle/noidle/speaking/turn_end/backchannel/uncertain`）。三态与其中三类对齐：

```
state_head.weight[0] ← vad_lm_head.weight[35]   # 静默           ← idle
state_head.weight[1] ← vad_lm_head.weight[37]   # 说话-incomplete ← speaking
state_head.weight[2] ← vad_lm_head.weight[38]   # 说话-complete   ← turn_end
```
→ day-0 就不是随机头。探针 A（0.99）已证完整性在 hidden 里**线性可读**，三态小头足够。

### 3.2 判别式，不走生成式 ✅
状态**不占词表槽位、不进 text 流**。依据：线性可读 → 判别式够；低延迟、不 generate、
K 个头天然并行、评测直接出 AUC、可独立降级。
（X2-Turn 用"整词表 + 保留 id"是为 checkpoint 兼容标准 LM 工具链；我们不守冻结范式，没这约束。）

### 3.3 per-face ASR 流 ✅
第 k 条流的 text 流就是**第 k 张脸的转写**。静默时输出 `STREAMING_PAD_ID`。
这条流既是输出，也是**条件化是否真的起作用的直接证据** —— 见 §5.3 的标签设计。

### 3.4 addressee ✅ + 弃权规则
per-face 二分类 `{对系统说 · 不对系统说}`，与状态正交。
**⚠️ 硬规则**：`others` 流的 `addr_logits` **永久丢弃**；人脸流在 `valid_k[t] = 0`
（无脸/极侧脸/遮挡）时 `addr_logits` **也必须被系统层丢弃**，
不得强行二选一 —— 注视信息只存在于视觉，无视觉时该头只能从音频 hidden 编造。
弃权由**前置模块的确定性 mask** 执行，不是学出来的。

### 3.5 系统层（不属模型 forward）
`state` × `addressee` × `ASR 文本` → "该不该现在回应他 / 回应谁"。
阈值、迟滞、uncertain 兜底、多脸同时 complete 的仲裁，全在系统层。

## 4. ★ 三种运行情形的完整流程

> **统一机制，无 if-else 分支。** 流的集合恒为 `{画面内 K_t 张脸} ∪ {others}`，恒 ≥ 1 条。
> 三种"情形"只是 `K_t = 0 / 1 / ≥2` 这一个变量的取值；真正在变的不是**有几条流**，
> 而是**这段音频落到哪条流上**。

### 4.0 统一视角：音频总要有个归宿

```
                      ┌─ face_1 ─┐
  一段混音的每一帧 ──►│    ⋮      │─► 恰好落在这 K+1 条流的某一条（重叠时可落多条）
                      ├─ face_K ─┤
                      └─ others ─┘   ← 兜住"归不到任何可见人脸"的语音
```
没有一帧语音会无家可归，也没有"流的数量为 0"的状态。下面三节只是把这张图在不同 `K_t` 下展开。

---

### 4.1 情形 1 · 有音频，画面中**没有人** （`K_t = 0`，流数 = 1）

```
音频 ──►[Whisper ×1]──► 音频 token
                          │
                          ▼   唯一的流：others，条件 = E_others（可学习嵌入）
                    ┌──────────────────┐
                    │ LLM  batch = 1   │
                    └────────┬─────────┘
                             ▼
      asr_logits   → 画外那个人的转写
      state_logits → 三态有效：静默 / 说话-incomplete / 说话-complete
      addr_logits  → ★ 永久弃权（看不见的人，注视无从判断）
```

**输出语义**：`{track_id: "others", state, text, addressee: 弃权}`
—— "**有个我看不见的人在说话，而且他（没）说完**"。

这比 v6 的 null 流语义更准：v6 输出的是一条"无归属"的匿名流，v6.1 输出的是
"**归属于画外**"的具名流。对机器人下游是两种不同的决策依据（前者"不知道谁"，后者"确定不是眼前这些人"）。

**⚠️ 诚实边界（两条）**：
1. 画外若有**多人同时说**，`others` 拿到的就是探针实测塌到 **0.47** 的那个混合表征
   → 系统层必须按低置信处理，**不得**把它当可靠判决。
2. `K_t=0` **不等于**"纯 X2-Turn"（`E_others ≠ 0`）。逐比特退化是**视觉整体失效**时才触发的
   另一条路径（§2.6 末表）。

---

### 4.2 情形 2 · 有音频，画面中**只有一人** （`K_t = 1`，流数 = 2）

```
音频 ──►[Whisper ×1]──► 音频 token ──┬─ v_1       ──► 流 face_1: asr/state/addr
                                      └─ E_others ──► 流 others: asr/state/(弃权)
                                         batch = 2
```

必须分清的**两个子情形**，期望输出完全相反：

| 子情形 | `face_1` | `others` | 靠什么做到 |
|---|---|---|---|
| **2a · 音频就是这个人发的** | `state ∈ {incomplete, complete}`；ASR = 他的话；addressee 由注视定 | **静默 + 全 PAD** | 探针 A 的 regime（0.99）；视觉主要贡献**归属确认**与 **addressee** |
| **2b · 音频来自画面外**（镜头前这位沉默） | **静默 + 全 PAD** | `state ∈ {incomplete, complete}`；ASR = 画外那句话 | **只能靠视觉**：唇不动 ⇒ 条件化判定"不属于我" |

> **★ 2b 仍是整个架构最关键的负样本，但 `others` 让它变得可训练得多。**
> 一个没被正确训练的条件化模型会把听到的任何语音都转写到眼前唯一那张脸上（"有嘴就是他说的"）。
> 防线现在有**三道**：
> ① 训练集必须含"脸在画面、音频来自他处"的样本；
> ② 静默脸的 ASR 标签是**全 PAD**（负向监督，§5.3）；
> ③ **`others` 流有正向目标**——那句话必须被它转写出来（v6.1 新增，比 ② 强）。
>
> **2b 上的表现 = "条件化是否真的在做提取"的判据。** 若 2b 崩了（face_1 抢了画外的话），
> 说明视觉被忽略，B 路线退化成带装饰的 X2-Turn。⏳ 必须进恢复实验的评测集。

### 4.3 情形 3 · 有音频，画面中**多人** （`K_t = K ≥ 2`，流数 = K+1）

```
音频 ──►[Whisper ×1]──► 音频 token（全部流共享同一份）
                              │
   face_1 ─►[视觉塔]─► v_1 ───┤                    ┌──► 流 1:      asr/state/addr  (KV cache 1)
   face_2 ─►[视觉塔]─► v_2 ───┤  batch = K+1       ├──► 流 2:      asr/state/addr  (KV cache 2)
      ⋮                       │  同权重 同音频      │        ⋮
   face_K ─►[视觉塔]─► v_K ───┤  异条件 异 text 流  ├──► 流 K:      asr/state/addr  (KV cache K)
            E_others ────────┘                    └──► 流 others: asr/state/弃权  (KV cache K+1)
```

四个子情形：

| 子情形 | 期望输出 | 把握 |
|---|---|---|
| **3a · 一人说，其余静默**（多数情形） | 说话者那条流出文本 + incomplete/complete；其余脸 + `others` 全 PAD + 静默 | 这是**归属**任务，探针 B 已证视觉可做（说话人身份 acc 0.649 vs 随机 0.25） |
| **3b · 两人及以上重叠** | 各流分别提取各自的内容与完整性；`others` 静默 | ⚠️ **最难，C2 的判据**。混音表征已退化（0.47），条件化能捞回多少是**经验问题** → ⏳ 恢复实验量化；捞不回则系统层输出 uncertain |
| **3c · 无人说话**（静音/环境噪声） | 全部 K+1 条流 = 静默 + 全 PAD | 三态的"静默"类直接覆盖；噪声**不**进 `others`（§2.6 限制条款） |
| **3d · 音频来自画面外，K 张脸都沉默** | K 张脸全静默 + 全 PAD；**`others` 转写它** | **v6 在这里有洞**（音频无处可去），v6.1 由 `others` 补上 |
| **3e · 画内有人说 ＋ 画外也有人说**（混合） | 对应人脸流出文本；`others` **同时**出文本 | v6 完全无法表达；v6.1 天然支持（流间不互斥，§2.3） |

**两条不变量**（系统层可据此做一致性检查）：
- **置换等变**：打乱人脸顺序，输出跟着打乱、内容不变（流间无通信 ⇒ 结构上天然成立，§6.4 守住）。
  `others` 恒定排在末位，不参与置换。
- **不强制划分**：允许 0 条流说话（3c），也允许多条流同时说话（3b/3e）。
  "K+1 条转写应拼成完整混音"**不是**硬约束，只是 PAD 监督带来的软倾向（§2.3）。

**成本**：Whisper 编码 `1×` + LLM `(K+1)×`（batched decode）。
相对 v6 只多一条流（`+1/K`）；`K=0` 时反而与 v6 的 null 流成本相同。K=4 / 4B / 12.5 Hz 在 2×H20 上可行；`K ≥ 8` 的降级见 §7.5。

## 5. 训练契约

### 5.1 阶段
- **S1**：冻骨干（含音频编码器），只训 **视觉塔 + 门控 cross-attn + 三个头**；门控从 0 长起来。
  验收：归属/状态可读、ASR 不坏、恒等性单测仍过。
- **S2**：骨干开 **LoRA r=32**（数据量足则全微调），一次前向联合训。

### 5.2 损失
```
L = L_asr + λ_s · Σ_k L_state(k) + λ_a · Σ_k L_addr(k)
```
- `L_state` 类加权：**incomplete 被误判为 complete（= 抢话）代价最高**。
- `L_addr` 只在**人脸流**且 `valid_k=1` 的帧上计算；**`others` 流不计 addressee 损失**（§3.4）。
- ⚠️ `others` 的 `L_state` / `L_asr` 需**下调权重或做类平衡**，防止它变成垃圾桶（§7.5）。
- **视觉 dropout `p≈0.3`**（整段置零）→ 把"视觉失效可降级"从结构保证升级为统计保证，
  同时它就是在**批量制造情形 1**，让 null 流路径被真正训练过。

### 5.3 ★ 标签设计：每帧语音都要有归宿，其余流一律全 PAD
让条件化"真的在做提取"的核心监督，也是 §4.2b / §4.3d / §4.3e 的防线。
**对称地施加在 K+1 条流上**：

```
face k 在帧 t 静默     ⇒  asr_label[k,t] = STREAMING_PAD_ID   且  state_label[k,t] = 0
face k 在帧 t 说话     ⇒  asr_label[k,t] = 他自己的词 token   且  state ∈ {1,2}

others 在帧 t 无画外音 ⇒  asr_label[o,t] = STREAMING_PAD_ID   且  state_label[o,t] = 0   ← 与人脸流对称
others 在帧 t 有画外音 ⇒  asr_label[o,t] = 画外那句的词 token 且  state ∈ {1,2}
```

两条监督方向相反、互相夹住：
- **负向**（人脸流的 PAD）：惩罚"抢别人的话"。若缺失，最省力解是**忽略视觉**、每条流复述混合 ASR
  —— 那恰好就是消融臂 A 的行为。
- **正向**（`others` 的词标签）：画外语音有明确去处。若缺失（v6 的做法），
  模型只知道"这不是你说的"，不知道"那是谁说的"，2b/3d 的监督信号弱得多。

⚠️ **`others` 的 PAD 标签不可省**：只在有画外音时监督它、其余时刻放任，会直接养出 §7.5 的垃圾桶解。

### 5.4 标签形态（C1 数据集必须产出的接口）
每段视频 × 每 80 ms 帧 × **每条流（K 条人脸轨迹 ＋ 1 条 others）**：
`{track_id | "others", valid, state ∈ {0,1,2}, addressee ∈ {0,1,弃权}, text token}`
＋ 段级元信息：`是否含画面外说话人`（情形 2b/3d/3e 的采样需要）。

> **★ 这条对 C1 的标注流程有实质要求**：标注员必须能判定"这句话是画面里谁说的，还是画面外的人说的"。
> 会议室第三人称机位（AMI）里这件事相对容易；自采第一人称/机器人视角下，
> 画外说话人是**常态**，必须在录制脚本里**刻意设计**并标注。
⏳ 数据方案（自建 vs 扩展 AVCocktail）见 cvpr-framing §5 backlog 5。

## 6. 必测单测 ✅

1. **恒等性**：所有 `α=0`（或**全部** `v:=0`，含 `v_others`）→ 输出与纯 X2-Turn **逐比特相同**。
   ⚠️ 这**不再**等价于情形 1：`K_t=0` 时 `E_others ≠ 0`，走的是另一条路径（§2.6 末表）。
2. **帧对齐脉冲响应**：第 n 帧注入视觉脉冲，响应必须出现在第 n 帧而非 n±1（守 §2.4 的 480 ms 坑）。
3. **零初始化**：新头 / 新门控在 step 0 的输出与梯度符合预期。
4. **置换等变**：打乱脸的顺序，输出随之置换且数值不变（守 §4.3 的不变量）。
5. **变长 K**：`K = 0 / 1 / 4 / 8`，流数恒为 `K+1`；人中途进出时形状、mask、`others` 恒在末位。
6. **归属行为（2b 回归测试）**：喂"脸在画面但不说话 + 画外语音"，
   断言 **face 流全 PAD 且 others 流出文本** —— 两侧都要断言，只断言一侧测不出垃圾桶解。
7. **`others` 不吞画内语音（3a 回归测试）**：喂"画面内某人在说、无画外音"，断言 **others 全 PAD**。
   这是 §7.5 的守门单测。

## 7. 已知风险与边界

### 7.1 重叠段（情形 3b） ⏳
混音表征已退化（噪声 gate 0.47）。B 路线**假设**表征层条件化能把目标捞回 —— 这是经验问题，
由恢复实验量化。低置信 → 系统层 uncertain。**这是 C2 是 headline 还是降级为 strong baseline 的判据。**

### 7.2 视觉被忽略的退化解 ⚠️
若 PAD 监督不足或视觉塔容量不够，模型会收敛到"忽略 `v_k`、每条流复述混合 ASR"。
**检测手段**：情形 2b / 3d 的表现；以及门控 `α` 的量级。**这是训练期必须盯的第一指标。**

### 7.3 新流冷启动
人进画面时该流无历史上下文（§2.5），前几百 ms 判决不可信 → 系统层按 uncertain 处理。

### 7.4 ⚠️ `others` 退化成垃圾桶
`others` 的镜像风险：模型发现归属很难，就把拿不准的语音一股脑丢进 `others`（反正那里总有个合法去处），
人脸流集体摆烂输出 PAD。这与 §7.2 是同一枚硬币的两面。
**防线**：① `others` 在无画外音时也必须监督为全 PAD（§5.3）；② 损失权重下调 / 类平衡（§5.2）；
③ §6 第 7 条守门单测；④ 训练期盯**画内语音被判给 `others` 的比例** —— 比总 loss 灵敏得多。

### 7.5 成本
`1×` Whisper + `(K+1)×` LLM。K=4 可行；`K≥8` 时的降级方案 = **状态头走共享前向（消融臂 A 的路径）
覆盖全部 K 脸，ASR 流只对 `state≠静默` 的脸开** —— 即 cvpr-framing §3.2 的"读出/ASR 解耦"，
定位为**部署期优化**，不是论文主模型。

## 8. 与 v5 / 消融臂的关系

### 8.1 消融臂 A（原 v5 方案）
"共享单次前向 + 事后 per-face cross-attn 读出"= **把门控关掉、改为在 `H[t]` 之后做读出**。
它是 B 的**严格子集** → 做 B 白送 A 的同构消融，直接服务 C3 的消融要求。
A 的两处结构性缺陷（也正是降为消融臂的理由）：给不了 per-face ASR；完整性读自混合 hidden（撞 0.47）。

### 8.2 变化清单

| 项 | v5 | v6 | 原因 |
|---|---|---|---|
| 视觉进入位置 | 骨干**之后**读出 | **骨干之内**逐层零初始化门控注入 | A 的完整性读自混合 hidden |
| 粒度 | K 套 vs 单流未定 | **K 条流（batch 维）**，共享音频编码 | per-face ASR 是 setting 承诺的能力 |
| 状态读出 | 判别式/生成式未定 | **判别式** + 从 `vad_lm_head` 行热启动 | 探针 A 线性可读 |
| addressee | 删去 | **第 4 个 per-face 输出**，带弃权规则 | cvpr-framing §1 提级 |
| 视觉输入 | 整帧 RGB，编码器内部检测 | **前置冻结检测跟踪 → per-face crop + valid** | 整帧 ViT 给不了 per-face token |
| 画外说话人 | **无处安放**（旧 3d 的音频凭空消失） | **常驻 `others` 流**（可学习嵌入，addressee 永久弃权） | 归属完全覆盖 ＋ 正样本监督（§2.6） |
| K=0 | 未定义 | 就是「只有 `others` 一条流」，**不再是特例** | 情形 1（§4.1） |
| 骨干 | Voxtral/X2-Turn 未细化 | **X2-Turn-4B-0812**，参数已核 | cvpr-framing §8 |
