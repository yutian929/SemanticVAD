## 0. 一页纸总览

```
                        ┌─── 前置冻结模块（不参与梯度）────┐
  单目 RGB (多人同框) ──►│  人脸检测 + 跟踪 → K_t 条轨迹    │──► 每脸: 脸/嘴 crop + 头姿/注视 + valid 标志
                        └───────────────┬─────────────────┘
                                        ▼
                              ┌────────────────────┐
                              │ 视觉塔（共享权重）  │──► v_k[t] ∈ R^3072   每脸每 80ms 一个 token
                              └─────────┬──────────┘
                                        │ 零初始化门控 cross-attn，第 k 条流只看 v_k
  多人混合音频 ──►[Whisper enc ×1]──►[adapter]──►┌─────────────────────────────┐
     16 kHz          （全 K 条流共享）  12.5Hz    │  Voxtral LLM 26 层 d=3072    │
                                       80ms/tok  │  ★ batch 维 = K_t 条 per-face │
                                                 │    流，各自 KV cache          │
                                                 └──────────────┬───────────────┘
                                                                ▼ H_k[t]  每脸独立 hidden
                                        ┌───────────────────────────────────────┐
                                        │ forward 只吐 logits（每脸 × 每帧）     │
                                        │  asr_logits   [B,K,T,131072]          │
                                        │  state_logits [B,K,T,3]               │
                                        │  addr_logits  [B,K,T,2]               │
                                        └───────────────────────────────────────┘
                                                     ← 模型到此为止；解码与仲裁属系统层（§3.5）
```

**一句话**：混合音频只编码一次，**每张脸各开一条被自己视觉条件化的 LLM 流**；
每条流独立地回答"这段混音里属于我的是什么、我说完没、我在对谁说"。

## 1. 输入契约 ✅

### 1.1 音频

| 项 | 值 | 依据 |
|---|---|---|
| 形态 | **多人混合**单通道波形，16 kHz | cvpr-framing §1（不用麦阵 / DoA） |
| 前端 | Whisper-large-v3 编码器，`num_mel_bins=128`，`hidden=1280`，32 层 | `config.json: audio_config` |
| 降采样 | adapter `downsample_factor=4` → LLM token 流 | `config.json: downsample_factor` |
| **帧率** | **12.5 Hz = 80 ms / token** | `audio_length_per_tok=8 × hop_length=160 ÷ 16000`（`inference.py:118-119`） |
| LLM | `hidden_size=3072`，26 层，`vocab=131072` | `config.json: text_config` |
| **前瞻延迟** | `default_num_delay_tokens=6` → **480 ms** | `inference.py:122`；对齐规则见 §2.4 |

> **★ 音频编码器只跑一次。** K 条流吃的是同一份 `input_features`，
> Whisper 编码器（32 层 / 1280 维）与 adapter 属**共享前缀**，`1×`；
> 只有 LLM 解码器是 `K×`。这是 B 路线成本的真实构成（§7.4）。

### 1.2 视频

| 项 | 值 |
|---|---|
| 形态 | **单目 RGB**，多人同框 |
| 前置模块（冻结、不训） | 人脸检测 + 跟踪 → 第 t 帧给出 `K_t` 条稳定轨迹 |
| 每条轨迹产出 | ① 脸/嘴 ROI crop；② 头姿 + 注视向量；③ **`valid_k[t] ∈ {0,1}`**（是否拿到可信人脸） |
| 时间对齐 | 重采样到 **12.5 Hz**（25 fps → 每 80 ms 取末帧；50 fps → 池化） |
| `K_t` | **变长**，0 起步，允许人中途进出（流的生老病死见 §2.5） |

**`valid_k[t]` 是契约的一部分，不是实现细节**：它驱动 §4 三种情形的分流，
也决定 addressee 输出是否可信（无脸 / 极侧脸 → 注视不可读 → addressee 必须弃权，见 §3.4）。

## 2. 中间流程

### 2.1 视觉塔 💡（选型待拍板，接口已定）

```
crop_k[t]  ─►[视觉编码器: 预训练唇动/脸动塔]─► e_k[t] ∈ R^d_v
pose_k[t]  ─►[小 MLP]───────────────────────► g_k[t] ∈ R^d_g
                  concat → Linear(d_v+d_g → 3072) → v_k[t]
valid_k[t] = 0  ⇒  v_k[t] := 0            # 硬置零，不是学出来的
```

- 编码器候选：💡 **AV-HuBERT 视觉前端**（唇动，96×96 ROI，自监督预训练，输出序列表征）
  vs Light-ASD / TalkNet（ASD 预训练，但输出偏二分类 logit，不适合当条件源）。
- **注视/头姿走独立支路**，不能被唇动塔吞掉 —— addressee 轴只靠它（cvpr-framing §3.2）。
- 每脸每帧 **1 个 token** 起步；不够再升到 n 个（超参，不改契约）。

### 2.2 per-face 条件化 —— ★ 核心机制 ✅

**面孔 k 的 visual token，通过零初始化门控 cross-attention 注入第 k 条流的 LLM 各层。**

```
第 k 条流、LLM 第 ℓ 层（每 N≈4 层插一个）:
    h ← h + tanh(α_ℓ) · CrossAttn(Q = h, K = V = v_k[≤t])      α_ℓ init 0
```

- **因果**：位置 t 只看 `v_k[≤t]`。
- **零初始化**：`α=0` 或 `v_k≡0` 时该流**逐比特等于纯 X2-Turn**。
  这一条同时是：恒等性单测（§6.1）、视觉失效的降级保证（§4.1）、以及 K=0 情形的定义。
- **流间不共享、不通信**：第 k 条流只看 `v_k`，**没有任何 cross-face 注意力**。
  这是与 MuVAP 的结构性差异（它把 N 人塌成 2 态；我们任意 K、置换等变、不塌）。
- **新增参数**只有：视觉塔 + 门控 cross-attn + 三个头；骨干走 LoRA。

> **⚠️ 新颖性口径（不可犯）**：该机制 = **AV-TSE 的表征空间版本**，机制**不新**
> （CueNet / Plug-and-Steer / USEF-TSE，cvpr-framing §7）。论文**绝不能**写
> "首个视觉引导 per-face 提取/路由"；卖点钉在**输出是 per-face 语义状态而非波形**。

### 2.3 为什么不加 cross-face 归一化 ✅

自然的诱惑是在 K 条流之间做 softmax（"这帧属于谁"）。**不做**，两条理由：

1. 真重叠时多人同时说，"归一化到 1"是错的前提 —— 这正是 VAP 家族塌成 floor-holder 的起点。
2. **不需要**：静默脸的 ASR 标签是**全 PAD**（§5.3），这个监督已经在惩罚"抢别人的话"，
   竞争信号从标签进来，不必从结构进来。

保持 forward 逐脸独立 = 保住"真 per-face、任意 K"这条卖点。

### 2.4 ⚠️ 时间对齐（最容易静默写错的地方）

**只用一条索引规则，不发明第二套**：X2-Turn 的读出偏移是

```
prediction_index = prefix_length + frame_index - 1        # inference.py:165，next-token 语义
```

→ **墙钟帧 `i` 的 visual token 注入到 LLM 位置 `prefix_length + i - 1`**，与音频帧 `i`、
状态读出位置**完全同一位置**。`num_delay_tokens=6`（480 ms）内生在音频特征的排布里，
意味着模型在该位置已看到 480 ms 的音频前瞻 —— 视觉按同一位置注入，就自动获得**同样的前瞻**，
视听前瞻一致。写错则视听错位 480 ms，且**不报错、只静默掉点** → 由 §6.2 脉冲响应单测兜住。

### 2.5 流的生老病死（变长 K 的流式处理）✅

| 事件 | 处理 |
|---|---|
| 新轨迹出生（有人进画面） | **新开一条流**，KV cache 从当前时刻冷启动（不回放历史）。前几百 ms 该流的语义上下文弱，`state` 置低置信 → 系统层按 uncertain 处理 |
| 轨迹存活 | 该流持续增量解码，维护自己的 KV cache |
| 轨迹丢失 / 人出画面 | 该流**销毁**，KV cache 释放 |
| 短暂遮挡（`valid=0` 但轨迹未死） | 流**保留**，`v_k[t]:=0` → 这几帧退化为纯音频行为，恢复后继续 |
| 人离开又回来 | **算新轨迹、新流**（v5 起就不做身份 enroll / re-ID，保持最简） |

⚠️ **冷启动是 B 路线的固有代价**：新出现的脸拿不到它出现之前的音频上下文。
⏳ 是否需要"有界回放"（新流补跑最近 N 秒音频）留作实现期实验，不进 v6 契约。

## 3. 输出契约 ✅（forward 只吐 logits）

对每张脸 `k ∈ [1..K_t]`、每个 80 ms 帧 `t`：

| 输出 | 形状 | 实现 | 热启动 |
|---|---|---|---|
| `asr_logits` | `[B,K,T,131072]` | 复用 `base_model.lm_head` | ✅ 继承 X2-Turn |
| `state_logits` | `[B,K,T,3]` | **新** `Linear(3072,3,bias=False)` | ✅ 拷 `vad_lm_head` 第 35/37/38 行 |
| `addr_logits` | `[B,K,T,2]` | **新** `Linear(3072,2,bias=False)` | ❌ 随机 |

### 3.1 状态三态 ✅
`{0 静默 · 1 说话-incomplete · 2 说话-complete}` —— active 与 completeness 天然耦合，单头即可。

**热启动**：`vad_lm_head` 是 `lm_head` 的整词表拷贝，只有 id 35–40 有意义
（`modeling.py:15-23`：`idle/noidle/speaking/turn_end/backchannel/uncertain`）。三态与其中三类对齐：

```
state_head.weight[0] ← vad_lm_head.weight[35]   # 静默           ← idle
state_head.weight[1] ← vad_lm_head.weight[37]   # 说话-incomplete ← speaking
state_head.weight[2] ← vad_lm_head.weight[38]   # 说话-complete   ← turn_end
```
→ day-0 就不是随机头。探针 A（0.99）已证完整性在 hidden 里**线性可读**，三态小头足够。

### 3.2 判别式，不走生成式 ✅
状态**不占词表槽位、不进 text 流**。依据：线性可读 → 判别式够；低延迟、不 generate、
K 个头天然并行、评测直接出 AUC、可独立降级。
（X2-Turn 用"整词表 + 保留 id"是为 checkpoint 兼容标准 LM 工具链；我们不守冻结范式，没这约束。）

### 3.3 per-face ASR 流 ✅
第 k 条流的 text 流就是**第 k 张脸的转写**。静默时输出 `STREAMING_PAD_ID`。
这条流既是输出，也是**条件化是否真的起作用的直接证据** —— 见 §5.3 的标签设计。

### 3.4 addressee ✅ + 弃权规则
per-face 二分类 `{对系统说 · 不对系统说}`，与状态正交。
**⚠️ 硬规则**：`valid_k[t] = 0`（无脸/极侧脸/遮挡）时，`addr_logits` **必须被系统层丢弃**，
不得强行二选一 —— 注视信息只存在于视觉，无视觉时该头只能从音频 hidden 编造。
弃权由**前置模块的确定性 mask** 执行，不是学出来的。

### 3.5 系统层（不属模型 forward）
`state` × `addressee` × `ASR 文本` → "该不该现在回应他 / 回应谁"。
阈值、迟滞、uncertain 兜底、多脸同时 complete 的仲裁，全在系统层。

## 4. ★ 三种运行情形的完整流程

> 三种情形共用同一套 forward，差别只在 `K_t` 与 `valid_k`。**没有 if-else 分支代码**——
> 分流是由"`v_k=0` ⇒ 该流退化为纯音频"这一条结构性质自动产生的。

### 4.1 情形 1 · 有音频，画面中**没有人** （`K_t = 0`）

```
音频 ──►[Whisper ×1]──► 音频 token
                          │
                          ▼   注入一条 null 流：v_null ≡ 0
                    ┌──────────────────┐
                    │ LLM  batch = 1   │   ← 门控无贡献 ⇒ 逐比特 = 纯 X2-Turn
                    └────────┬─────────┘
                             ▼
      asr_logits   → 一条**无归属**的转写（"有人在说这句话"，但不知是谁）
      state_logits → 三态仍然有效（探针 A 的 0.99 就是这个 regime）
      addr_logits  → ★ 丢弃（valid=0）
```

**做法**：`K_eff = max(K_t, 1)`，补一条 `v≡0` 的 **null 流**。

**输出语义**：`{track_id: null, state, text, addressee: unknown}`。
系统仍然知道"有人在说 / 说完没"，只是**不知道是谁、也不知道是不是在对我说**。

**为什么这样设计而不是"不输出"**：
1. 这正是 §6.1 恒等性单测在推理期的同一条路径 —— 不需要额外代码，也不会有未测过的分支。
2. 无脸是**常态的瞬时事件**（跟踪丢失、转身、走出画面），不是异常；静默期若完全没有输出，
   下游状态机会被"信号消失"和"判静默"两种情况混淆。
3. 这条降级路径的质量有下界保证：它就是 X2-Turn 本身，而 X2-Turn 在单人干净下 AUC 0.99。

**⚠️ 诚实边界**：混音里若同时有多人说话而画面无人，null 流拿到的就是探针实测**塌到 0.47** 的那个
混合表征 → 系统层必须据此输出低置信/uncertain，**不得**把这条无归属流当成可靠判决。

### 4.2 情形 2 · 有音频，画面中**只有一人** （`K_t = 1`）

```
音频 ──►[Whisper ×1]──► 音频 token ──┐
face_1 ──►[视觉塔]──► v_1[t] ────────┤（门控注入）
                                      ▼
                            ┌──────────────────┐
                            │  LLM  batch = 1  │
                            └────────┬─────────┘
                                     ▼
            asr_logits[1] · state_logits[1] · addr_logits[1]
```

必须分清的**两个子情形**，它们的正确输出完全相反：

| 子情形 | 期望输出 | 靠什么做到 |
|---|---|---|
| **2a · 音频就是这个人发出的** | `state ∈ {incomplete, complete}`；ASR = 他的话；addressee 由注视决定 | 这是探针 A 的 regime（0.99）；视觉在此主要贡献**确认归属**与**addressee** |
| **2b · 音频来自画面外的人**（镜头前这位沉默） | `state = 静默`；ASR = **全 PAD**；addressee 弃权（他没在说） | **只能靠视觉**：唇不动 ⇒ 条件化把这段音频判为"不属于我" |

> **★ 2b 是整个架构最关键的负样本。** 一个没被正确训练的条件化模型，会把听到的任何语音都
> 转写到眼前唯一那张脸上（"有嘴就是他说的"）。防线有两道：
> ① 训练集**必须**含"脸在画面、音频来自他处"的样本；② 静默脸的 ASR 标签是**全 PAD**（§5.3）。
> **2b 上的表现是"条件化是否真的在做提取"的判据** —— 若 2b 崩了，说明视觉被忽略、
> 整个 B 路线退化成带装饰的 X2-Turn。⏳ 这条应进恢复实验的评测集。

### 4.3 情形 3 · 有音频，画面中**多人** （`K_t = K ≥ 2`）

```
音频 ──►[Whisper ×1]──► 音频 token（K 条流共享同一份）
                              │
   face_1 ─►[视觉塔]─► v_1 ───┤                    ┌──► 流 1: asr/state/addr  (KV cache 1)
   face_2 ─►[视觉塔]─► v_2 ───┤  batch = K         ├──► 流 2: asr/state/addr  (KV cache 2)
      ⋮                       │  同权重 同音频      │        ⋮
   face_K ─►[视觉塔]─► v_K ───┤  异视觉 异 text 流  └──► 流 K: asr/state/addr  (KV cache K)
                              ▼
                     ┌──────────────────┐
                     │  LLM  batch = K  │   流间无 cross-attn、无归一化（§2.3）
                     └──────────────────┘
```

四个子情形：

| 子情形 | 期望输出 | 把握 |
|---|---|---|
| **3a · 一人说，其余静默**（多数情形） | 说话者那条流出文本 + incomplete/complete；其余流全 PAD + 静默 | 这是**归属**任务，探针 B 已证视觉可做（说话人身份 acc 0.649 vs 随机 0.25） |
| **3b · 两人及以上重叠** | 各流分别提取各自的内容与完整性 | ⚠️ **最难，也是 C2 的判据**。混音表征已退化（0.47），条件化能捞回多少是**经验问题** → ⏳ 恢复实验量化；捞不回则系统层输出 uncertain |
| **3c · 无人说话**（静音/环境噪声） | 全部 K 条流 = 静默 + 全 PAD | 三态里的"静默"类直接覆盖 |
| **3d · 音频来自画面外，K 张脸都沉默** | 全部 K 条流 = 静默；这段音频**无归属** | 2b 的多人版；同样靠 PAD 负样本训练 |

**两条不变量**（系统层可据此做一致性检查）：
- **置换等变**：把脸的顺序打乱，输出跟着打乱、内容不变（流间无通信 ⇒ 结构上天然成立，由 §6.4 单测守住）。
- **不强制划分**：允许 0 条流说话（3c/3d），也允许多条流同时说话（3b）。
  "K 条转写应当拼成完整混音"**不是**硬约束，只是 PAD 监督带来的软倾向（§2.3）。

**成本**：Whisper 编码 `1×` + LLM `K×`（batched decode）。K=4 / 4B / 12.5 Hz 在 2×H20 上可行；
`K ≥ 8` 的降级策略见 §7.4。

## 5. 训练契约

### 5.1 阶段
- **S1**：冻骨干（含音频编码器），只训 **视觉塔 + 门控 cross-attn + 三个头**；门控从 0 长起来。
  验收：归属/状态可读、ASR 不坏、恒等性单测仍过。
- **S2**：骨干开 **LoRA r=32**（数据量足则全微调），一次前向联合训。

### 5.2 损失
```
L = L_asr + λ_s · Σ_k L_state(k) + λ_a · Σ_k L_addr(k)
```
- `L_state` 类加权：**incomplete 被误判为 complete（= 抢话）代价最高**。
- `L_addr` 只在 `valid_k=1` 的帧上计算（与 §3.4 的弃权规则一致）。
- **视觉 dropout `p≈0.3`**（整段置零）→ 把"视觉失效可降级"从结构保证升级为统计保证，
  同时它就是在**批量制造情形 1**，让 null 流路径被真正训练过。

### 5.3 ★ 标签设计：静默脸的 ASR 目标是全 PAD
这是让条件化"真的在做提取"的唯一监督来源，也是 §4.2b / §4.3d 的防线：

```
face k 在帧 t 静默  ⇒  asr_label[k,t] = STREAMING_PAD_ID  且  state_label[k,t] = 0
face k 在帧 t 说话  ⇒  asr_label[k,t] = 他自己的词 token  且  state ∈ {1,2}
```
若没有这条，模型最省力的解是**忽略视觉**、每条流都复述混合 ASR —— 而这恰好就是消融臂 A 的行为。

### 5.4 标签形态（C1 数据集必须产出的接口）
每段视频 × 每 80 ms 帧 × 每条人脸轨迹：
`{track_id, valid, state ∈ {0,1,2}, addressee ∈ {0,1,弃权}, text token}`
＋ 段级元信息：`是否含画面外说话人`（情形 2b/3d 的采样需要）。
⏳ 数据方案（自建 vs 扩展 AVCocktail）见 cvpr-framing §5 backlog 5。

## 6. 必测单测 ✅

1. **恒等性**：所有 `α=0`（或 `v≡0`）→ 输出与纯 X2-Turn **逐比特相同**。等价于情形 1 的正确性。
2. **帧对齐脉冲响应**：第 n 帧注入视觉脉冲，响应必须出现在第 n 帧而非 n±1（守 §2.4 的 480 ms 坑）。
3. **零初始化**：新头 / 新门控在 step 0 的输出与梯度符合预期。
4. **置换等变**：打乱脸的顺序，输出随之置换且数值不变（守 §4.3 的不变量）。
5. **变长 K**：`K = 0 / 1 / 4 / 8`，以及人中途进出（流的新建与销毁）时形状与 mask 正确。
6. **PAD 行为**：喂"脸在画面但不说话 + 画面外语音"，该流应输出全 PAD（情形 2b 的回归测试）。

## 7. 已知风险与边界

### 7.1 重叠段（情形 3b） ⏳
混音表征已退化（噪声 gate 0.47）。B 路线**假设**表征层条件化能把目标捞回 —— 这是经验问题，
由恢复实验量化。低置信 → 系统层 uncertain。**这是 C2 是 headline 还是降级为 strong baseline 的判据。**

### 7.2 视觉被忽略的退化解 ⚠️
若 PAD 监督不足或视觉塔容量不够，模型会收敛到"忽略 `v_k`、每条流复述混合 ASR"。
**检测手段**：情形 2b / 3d 的表现；以及门控 `α` 的量级。**这是训练期必须盯的第一指标。**

### 7.3 新流冷启动
人进画面时该流无历史上下文（§2.5），前几百 ms 判决不可信 → 系统层按 uncertain 处理。

### 7.4 成本
`1×` Whisper + `K×` LLM。K=4 可行；`K≥8` 时的降级方案 = **状态头走共享前向（消融臂 A 的路径）
覆盖全部 K 脸，ASR 流只对 `state≠静默` 的脸开** —— 即 cvpr-framing §3.2 的"读出/ASR 解耦"，
定位为**部署期优化**，不是论文主模型。

## 8. 与 v5 / 消融臂的关系

### 8.1 消融臂 A（原 v5 方案）
"共享单次前向 + 事后 per-face cross-attn 读出"= **把门控关掉、改为在 `H[t]` 之后做读出**。
它是 B 的**严格子集** → 做 B 白送 A 的同构消融，直接服务 C3 的消融要求。
A 的两处结构性缺陷（也正是降为消融臂的理由）：给不了 per-face ASR；完整性读自混合 hidden（撞 0.47）。

### 8.2 变化清单

| 项 | v5 | v6 | 原因 |
|---|---|---|---|
| 视觉进入位置 | 骨干**之后**读出 | **骨干之内**逐层零初始化门控注入 | A 的完整性读自混合 hidden |
| 粒度 | K 套 vs 单流未定 | **K 条流（batch 维）**，共享音频编码 | per-face ASR 是 setting 承诺的能力 |
| 状态读出 | 判别式/生成式未定 | **判别式** + 从 `vad_lm_head` 行热启动 | 探针 A 线性可读 |
| addressee | 删去 | **第 4 个 per-face 输出**，带弃权规则 | cvpr-framing §1 提级 |
| 视觉输入 | 整帧 RGB，编码器内部检测 | **前置冻结检测跟踪 → per-face crop + valid** | 整帧 ViT 给不了 per-face token |
| K=0 | 未定义 | **null 流**，退化为纯 X2-Turn | 情形 1（§4.1） |
| 骨干 | Voxtral/X2-Turn 未细化 | **X2-Turn-4B-0812**，参数已核 | cvpr-framing §8 |
