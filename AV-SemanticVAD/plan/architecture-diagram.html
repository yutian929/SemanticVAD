相较现有模型，多了什么能力

现有模型（X2-Turn / SoulX）我们的模型
输入单人音频流（chunk）多人混合音频 + 单目 RGB 视频
隐含假设只有一个说话人画面里有多人、可能同时说
能力（系统交付）ASR 转写 + 完整性对画面内每个人：在不在说 · ASR · 完整性

多出来的三个功能（都由 RGB 里"谁的嘴在动"驱动）： ① 视频归属——把声音绑定到画面里正在说话的那个人； ② 重叠鲁棒的 per-speaker ASR——同时说话时靠各自唇动分给对的人分别转写； ③ per-speaker 完整性——分别判每个人说完没。
（这些是系统层交付；模型 forward 本身只吐 logits，见下。）

最简架构（模型部分 · 到 forward 输出为止）

音频通路 视觉通路 (RGB) 音频-LLM 骨干 (热启动) per-face 读出 forward 输出 (logits)

模型 forward 只到"每人一组 logits"为止（就像 X2-Turn/SoulX 只吐 logits）。 这些 logits 如何变成"在说? / 转写 / 完整性"，见下方 「从 logits 到结果」——那是 forward 之后的转换，且我们自己的输出形态尚未定。
视觉失效（黑暗/无脸）→ 退化为纯音频骨干。重度重叠 → 低置信 uncertain（恢复实验量化）。暂不做 addressee/enroll/DoA。

怎么应用 · 解决什么实际问题

场景模型提供的 substrate → 解决的问题
多人家庭机器人分别跟住每个人的话：知道孩子问完了→回应孩子；爸妈的交叉说话被正确归到他们名下、不误触发、不打断
实时字幕 / 会议记录逐人转写 + 逐人断句（谁说了什么、到哪断句）
全双工机器人话轮控制逐人"说完没"直接驱动"该不该接话"，避免抢话

"该回应谁"在最简版交给下游一条简单策略（谁刚说完一句完整的 / 谁在看机器人）；模型只负责给出逐人的（在说? · 转写 · 说完没）。

参考骨干 ① · X2-Turn（我们的热启动来源）· 模型 forward 输出

音频-LLM，共享 hidden 上双头：lm_head 与 vad_lm_head（后者是前者的拷贝）。 forward 只返回两个整词表 logits 张量；怎么变成转写/话轮见下方「从 logits 到结果」。

参考骨干 ② · SoulX-Duplug（"冻结前端 + Projector + LoRA"范式）· 模型 forward 输出

WhisperVQ(冻结) → 离散音频 token(80ms) → codebook + EncoderProjector(MLP) → 按 audio_mask 与文本 embeds 混合 → LLM(LoRA)。 forward 返回单个整词表 logits；complete/incomplete 是词表里的槽位（转换见下）。

从 logits 到结果（系统层 · forward 之后另做）

模型 forward 只吐 logits；下面是把 logits 变成"转写 / 完整性"的解码步骤，不在模型 forward 内。 logit 本身只是"下一个 token 的打分"，之所以能读出 complete/incomplete，是因为训练时用标签把某个词表槽位"指派"成了这个类（且完整性信息本就编码在 hidden 里，探针 A 可分性 0.99）。

模型logits → 转写logits → 完整性 / 话轮
X2-Turn对 logits 自回归 generate 解 token 流 → 去 PAD(32)/WORD(33)/id35–40 → detokenize每帧对 vad_logits 的 id 35–40 做 softmax → 6 类（turn_end/uncertain 承载完整性）
SoulX解同一条 token 流 → detokenize在判决位置读 complete/incomplete 状态 token 槽位的 logits，取大者
我们（待定）每人 token 流（若做 per-face ASR）每人 hidden 读出槽位 —— 判别式(读保留槽，仿 X2-Turn) 还是 生成式(状态 token，仿 SoulX)，待定
